# 3D 모델 성능 예산 (E-04 · 레인 1)

`app/glb_budget.py` + `scripts/glb_budget.py` — `.glb` 한 개가 **폰·노트북·데스크톱에서 얼마나 무거운지** 정적으로 계산한다(순수 파이썬 + Pillow: GPU·브라우저·네트워크 없음).

## 재는 것
삼각형 · 정점 · **그리기 호출**(메시 프리미티브 1개 = 1회) · 파일 크기 · **텍스처 GPU 메모리**(내장 그림을 RGBA로 풀었을 때 가로×세로×4바이트 + 밉맵 1/3, **같은 그림은 재질이 몇 개든 1번**) · 가장 큰 그림의 한 변.
**예산(제안값 — 설계 창이 정함; 대화형 WebGL 뷰어의 경험칙이지 이 제품의 측정이 아님)**
| 기기군 | 삼각형 | 그리기 호출 | 텍스처 MB | 파일 MB | 그림 한 변 |
|---|---|---|---|---|---|
| mobile | 100,000 | 50 | 64 | 20 | 2048 |
| laptop | 500,000 | 200 | 256 | 60 | 4096 |
| desktop | 2,000,000 | 500 | 1024 | 150 | 8192 |
초과하면 `check()`가 **얼마나 줄여야 하는지**(LOD 힌트: "삼각형 25% 이하로", "그림 한 변 약 N px")를 알려 준다. 판정 `passed`는 **알려진 모든 수치가 예산 안일 때만** True — 읽을 수 없는 값은 `unknown`으로 나오고 조용히 통과시키지 않는다.

## 이게 아닌 것 (정직하게)
- **FPS를 재지 않는다.** CI에는 GPU가 없고, 소프트웨어 GL의 프레임 시간은 폰에 대해 아무것도 말해 주지 않는다. 기기별 FPS 표는 **실제 기기에서 잰 뒤에야** 만들 수 있다(미실행).
- **LOD를 만들지 않는다.** 메시 단순화기가 승인되지 않았다 — 힌트만 준다.
- **압축 텍스처(KTX2/Basis, WebP)·주소로 가리키는 그림은 읽지 못한다** → `texture_bytes: null` + 경고.
- 애니메이션·스키닝·모프 비용, 셰이더 복잡도, 메모리 단편화는 보지 않는다.

## 우리 모델의 현재 수치 (`python scripts/glb_budget.py`)
| 모델 | 삼각형 | 그리기 | 파일 MB | mobile |
|---|---|---|---|---|
| base_male / base_female (R-ENGINE-08 몸) | 4,680 | 3 | 0.09 | ok |
| 샘플 의류 상의·바지·치마·원피스·재킷 | 560 / 1,600 / 200 / 600 / 1,840 | 1~3 | ≤0.02 | ok |
몸 + 재킷 + 바지를 한 장면에 두면 약 8,000 삼각형·9회 — 폰 예산의 8% / 18%. 시험(`tests/test_glb_budget.py`)이 "몸+옷 3점이 폰 삼각형 예산의 절반을 넘지 않는다"를 지켜서, R-ENGINE-08처럼 모델이 조용히 커지는 것을 잡는다(그때 몸이 912 → 4,680 삼각형, 13.6 → 97 KB가 됐다).
**텍스처는 아직 없다**(우리 생성 모델은 색만 쓴다) → 텍스처 열은 사용자가 올린 모델에서만 의미가 있다.
