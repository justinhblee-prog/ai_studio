# BUILD-00112 — Failure-Resilient Lookbook Export Retention Cleanup

## Implementation

- Reworked `scripts/cleanup_expired_lookbook_exports.py` into a dry-run-first, per-candidate cleanup operation.
- Storage keys must be a single filename; traversal, separators, NUL, empty values and dot segments are rejected.
- Cleanup opens the resolved private export directory and performs `stat(..., follow_symlinks=False)` plus `unlink(..., dir_fd=...)`. Symlinks and non-regular entries are never eligible for deletion.
- A missing file is counted separately. An `OSError` on one file is isolated so later candidates still run; the process exits with code 2 if any candidate failed.
- The database is read-only for cleanup. Append-only export audit rows are retained permanently.
- Added `tests/test_lookbook_export_cleanup.py` with 5 tests covering dry-run/apply, path traversal, symlink target protection, injected unlink failure and batch continuation, missing/non-regular entries, and immutable audit retention.

## Operational recovery procedure

1. Run `python scripts/cleanup_expired_lookbook_exports.py --limit 500` and retain the JSON output. This is read-only dry-run.
2. Review `invalid_paths`, `non_regular`, `missing`, and `would_remove`. Investigate invalid/non-regular entries; do not manually broaden deletion patterns.
3. Run `python scripts/cleanup_expired_lookbook_exports.py --apply --limit 500` only in the intended maintenance window. `removed` counts successful file removals; `failed` counts per-file errors. Exit code 2 means partial failure and requires a new dry-run after correcting the filesystem condition.
4. Re-run dry-run. Successfully removed files should now be reported as missing; their immutable audit rows remain available in export history. Do not delete or rewrite audit rows to make counts appear clean.
5. For a missing package whose audit row remains, record the discrepancy for investigation. Do not regenerate or overwrite the historical export under the same storage key. Create a new export only through the normal approval-gated API if a fresh package is needed.
6. Preserve private storage permissions and signing secrets. Never publish signed URLs or package files as public distribution; the package manifest does not grant publication or commercial rights.

## Boundaries

SQLite/local filesystem only. The directory-fd protections improve local cleanup safety but do not establish multi-host/object-storage semantics or production deployment readiness. G0-G5 remain unpassed.
