# 영상 음원 조사 (레인 4 · 6c, 회신 56 ⑫ · 답신 61)

**이 문서는 조사다.** 어떤 소리를 쓸 수 있게 할지는 **법무·대표 결정**이라 정하지 않았다(답신 61). 기술적으로 가능한 것만 코드(`app/video_mp4.py::add_audio`)로 확인했고, 그 함수는 **어떤 API 경로에도 연결하지 않았다**.

## 1. 선택지와 기술·운영 영향
| 안 | 내용 | 기술 영향 | 결정이 필요한 것(개발이 채우지 않음) |
|---|---|---|---|
| A 사용자 업로드 | 이용자가 소리 파일을 올려 영상에 넣음 | 새 자산 종류(오디오), 업로드 권리 확인 문구, 낯선 파일 해석 위험(아래 3), 용량·길이 한도, 삭제·보존 정책, 신고·임시 비공개(R-006) 경로 확대 | 음악 저작권 책임 소재, 권리 확인 문구, 신고 처리 기한 |
| B 서비스 제공 | 서비스가 고른 소리 목록을 제공 | 라이브러리처럼 읽기 전용 자산(출처·라이선스·권리 확인 필수 항목), 가져오기 도구, 내려가는 영상에 라이선스 고지 | 어떤 라이선스의 소리를 살 것인가(무료 공개·유료 구매), 결과 영상 재사용 조건 |
| C 둘 다 | A + B | A와 B의 합 | 위의 합 |
| D 무음 유지 | 소리를 넣지 않음 | 변경 없음 | 없음(현재 상태) |

## 2. 코드로 확인한 것 (`add_audio`, 연결 안 됨)
- 입력 소리는 **16비트 PCM WAV만**(모노·스테레오, 8~48kHz, 50MB·10분 이하). 표준 라이브러리 `wave`로 읽어 검사한다.
- 출력: 그림은 **다시 인코딩하지 않고 복사**(`-c:v copy`), 소리는 AAC 128kb/s, 앞부분 색인(faststart) 유지. 소리가 영상보다 길면 **자르고 마지막 1초를 줄여 끄며**, 짧으면 **뒤를 무음으로 채움**.
- 영상에 이미 소리가 있으면 거부, ffmpeg나 AAC 인코더가 없으면 `FFMPEG_MISSING`·`AUDIO_ENCODER_MISSING`으로 실패(다른 방식으로 조용히 바꾸지 않음).
- 시험(`tests/test_video_audio.py`)이 CI에서 실제로 확인: 소리 트랙 1개, 그림·프레임 수 그대로, 길이 ±0.15초, 소리가 들림(실효값), 끝 1/4초는 줄어듦, 긴 소리는 잘림, 짧은 소리 뒤는 무음, 스테레오·다른 표본 속도.

## 3. 위험과 열린 점
- **낯선 파일을 ffmpeg로 해석하는 위험**: 여러 형식(MP3·AAC·OGG…)을 받으려면 ffmpeg의 해석기가 낯선 바이트를 읽는다. 그래서 지금은 WAV만 받고, 다른 형식은 사용자 쪽에서 WAV로 바꿔 올리게 하는 안을 전제로 했다. 다른 형식을 받을지는 보안 검토가 필요하다(미검토).
- **저작권 확인은 기술로 할 수 없다.** 음악이 남의 것인지 자동으로 가려내는 기능은 만들지 않았고 조사하지도 않았다(외부 서비스 호출·비용 결정이 필요).
- **AI 표시와 소리**: 소리를 AI가 만들어 넣는 안(음악 생성 서비스)은 조사하지 않았다(공급자 호출·비용·약관 결정 필요). 지금 영상의 AI 표시는 파일 안 comment 태그에 들어가며 소리와 무관하다.
- AAC 인코더 라이선스: 쓴 것은 ffmpeg에 내장된 `aac` 인코더다. ffmpeg·인코더 배포 조건과 특허 사용료 해당 여부는 영상(H.264)과 같이 **미확인**이다(`docs/VIDEO_MP4.md`의 의존성 절 참고).
- 소리 길이와 영상 길이(5·10·15초)의 관계: 지금은 영상 길이에 맞춰 자른다. 사용자가 시작 지점을 고르게 할지는 결정되지 않았다.

## 4. 결정이 나면 이어서 할 일(제안, 승인 전 착수 안 함)
1. (A 또는 C) 오디오 자산 종류와 업로드 경로, 권리 확인 문구 자리. (B 또는 C) 소리 라이브러리 가져오기 도구와 출처 필수 항목.
2. 영상 작업 API에 `audio_item_id`(선택)와 소리 있음 표시, 출처 기록에 소리 자산 id.
3. 소리 길이·음량(일관성) 점검과 신고·삭제 경로 연결.
