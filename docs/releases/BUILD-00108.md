# BUILD-00108 — Lookbook Assembly from Individually Approved Photo Outputs

## Implementation

- Added immutable `lookbook_output_assets` and append-only `lookbook_output_export_events` to the shared Asset/Lookbook SQLite database. UPDATE/DELETE on attached output items and export events is blocked by database triggers.
- Added `GET /v1/lookbook-drafts/{draft_id}/outputs`, `POST .../outputs`, and `POST .../outputs/manifest`.
- Output attachment is allowed only after the Lookbook planning draft is approved and the referenced Photo run has succeeded and its exact output AssetVersion is individually approved.
- Attachment verifies the Photo review snapshot (Asset ID, immutable AssetVersion ID, Provenance ID, checksum) and rechecks the exact version file path/size/SHA-256 inside the Lookbook transaction.
- Product Variant association is allowed only when that Product or Variant is referenced by the approved Lookbook plan. Product SKU, Variant SKU and option values are snapshotted on the immutable Lookbook output item.
- A Lookbook can attach each Photo run once and uses a unique page order per draft. Correcting/reordering an immutable assembly requires a new Lookbook draft rather than mutating audit history.
- Output manifest revalidates every attached Photo output's latest approval snapshot and exact AssetVersion file integrity, then emits canonical JSON SHA-256 and an append-only export audit event.
- Manifest explicitly states each Photo output was individually approved but the assembled page sequence is **not separately approved**. It contains metadata only, no binaries/public URL, and sets publication/commercial rights flags false.
- `LookbookDraftWorkspace` discovers only individually approved Photo runs, attaches them to planned Product Variants, displays the SKU snapshot and exports the internal output manifest.

## Boundaries

- Only existing individually approved Photo outputs can be assembled. This does not create new AI images or call a Provider.
- The plan and each Photo output have their own approvals; the assembled page sequence has no separate approval workflow yet and is not publishable.
- Manifest is internal metadata only, not binary ZIP export, public distribution or commercial rights clearance.
- SQLite/local filesystem only. PostgreSQL/multi-host/production remain unverified. G0-G5 remain unpassed.
