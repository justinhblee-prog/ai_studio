# BUILD-00111 — Private Lookbook ZIP Package Export

## Implementation

- Added append-only `lookbook_output_package_exports` audit records with package SHA-256, byte size, manifest hash, approved assembly snapshot hash, output count, creation time and 24-hour expiry. UPDATE/DELETE is blocked by SQLite triggers.
- Added `POST /v1/lookbook-drafts/{draft_id}/outputs/package-export`, `GET .../outputs/exports`, and signed `GET /v1/lookbook-drafts/exports/{export_id}/download`.
- Package export requires an approved Lookbook plan, approved output assembly snapshot and individually approved Photo outputs. The exact immutable AssetVersion files are revalidated before ZIP creation and rechecked before the export audit commits.
- ZIP contains ordered image files under `pages/` plus canonical `manifest.json`. Each item includes page order, AssetVersion, SHA-256, size, Product/Variant SKU, caption and non-AI/provider/credit flags.
- Package manifest explicitly sets `internal_use_only=true`, `publication_authorized=false`, `public_distribution_authorized=false`, `commercial_rights_verified=false`, `binary_files_included=true`.
- Package limit: 100 output pages and 250 MiB total source bytes. Filenames are sanitized; package path is contained under private asset storage.
- Download URL is HMAC-signed for 15 minutes; package record/file expires after 24 hours. Download verifies package size/SHA-256 and returns private no-store attachment response.
- Added `scripts/cleanup_expired_lookbook_exports.py`. Dry-run is default; `--apply` deletes expired package files but retains immutable audit records.
- `LookbookDraftWorkspace` exposes internal ZIP creation only after separate assembly approval and displays the signed download link, expiry, size and checksum.

## Boundaries

- ZIP is a private internal-use handoff of already approved outputs. It does not grant copyright, likeness/consent, brand, publication, public distribution or commercial-use rights.
- Signed URL expires after 15 minutes; package retention expiry is 24 hours. Expired files require the dry-run-first cleanup script.
- SQLite/local filesystem only. PostgreSQL/object storage/multi-host/production remain unverified. G0-G5 remain unpassed.
