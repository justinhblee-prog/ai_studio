# BUILD-00097 — Product Variant / Option Catalog

## Implementation

- Added `product_variants` and `product_variant_assets` persistence with workspace-scoped parent Product, independent variant SKU, JSON option values and ACTIVE/ARCHIVED lifecycle.
- Added `POST/GET /v1/products/{product_id}/variants`, `PUT /v1/products/{product_id}/variants/{variant_id}` and `POST .../archive` APIs.
- Variant SKU shares one case-insensitive Workspace namespace with Product master SKU. All create/update operations serialize through SQLite `BEGIN IMMEDIATE` and reject cross-table collisions with HTTP 409.
- Option keys normalize to lowercase identifiers; option values are bounded non-empty strings. Variant-specific images, when supplied, must be active same-workspace image assets. Variant image references block deletion until the Variant is archived or updated.
- Archiving a parent Product archives its active Variants in the same transaction. Archived records and Product event history remain retained.
- Extended `ProductCatalogWorkspace` with basic size/color Variant creation and archive controls.

## Scope boundaries

- This is a flexible option-value foundation, not a full ERP variant system. No stock quantity, price, barcode, warehouse, tax, supplier, marketplace synchronization or external catalog import is implemented.
- Lookbook Draft currently references the parent Product, not an individually selected Variant. Variant-specific lookbook selection, asset resolution and output provenance remain next work.
- No live AI generation, Provider dispatch, billing or credits are involved.
- SQLite/local filesystem only. PostgreSQL, multi-host and production migration behavior are not claimed.
