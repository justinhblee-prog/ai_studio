# 실제 MP4 출력 (레인 4 · E-08a)

`ai_creator_studio_backend_starter/app/video_mp4.py` — 정지 그림 1~8장을 카메라 움직임이 있는 **실제 MP4**로 만든다. AI·외부 공급자·네트워크를 쓰지 않는다.

## 되는 것
| 항목 | 값 |
|---|---|
| 비율·크기 | 9:16 = 720×1280, 4:5 = 864×1080, 16:9 = 1280×720 |
| 길이 | 5·10·15초, 초당 24프레임(120·240·360프레임) |
| 움직임 | `zoom`(15% 다가감), `pan`(여유가 큰 방향으로 이동), `rotate`(−4°→+4°) |
| 장면 전환 | `cut`, `crossfade`(0.5초) |
| 파일 | H.264(`avc1`), yuv420p, faststart(앞부분에 색인), 소리 없음 |
| 점검 | `probe_mp4`: 파이썬만으로 MP4 구조 판독(코덱·크기·프레임 수·길이·faststart) / `qc_mp4`: ffmpeg로 다시 풀어 프레임마다 확인 |

`qc_mp4` 판정: **실패** = MP4 아님, 코덱·크기·프레임 수·길이 불일치, 디코드 오류, 빈 프레임. **경고만** = faststart 아님, 밝기 튐(컷 전환도 튄다), 움직이지 않는 화면.

ffmpeg가 없으면 `FFMPEG_MISSING`으로 **실패**한다. 다른 형식(WebP 등)으로 조용히 바꾸지 않는다. 실행 파일 위치는 PATH 또는 환경 변수 `FFMPEG_BINARY`.

## 안 되는 것 (다음 단계)
- **영상 작업 API에 연결되지 않았다.** `app/video_jobs.py`는 아직 mock의 움직이는 WebP를 준다. 연결하려면 자산 형식에 `video/mp4` 추가, 저장·내려받기·AI 표시 경로 확인이 필요하다.
- 3D 회전 영상은 모듈·명령줄까지만 있다(아래 E-08b). 3D 스튜디오 화면·API에서 부르는 경로는 없다.
- 소리, 자막·글자 넣기, 세로·가로 외 비율, 30/60fps, 1080p 초과 해상도 없음.
- 움직임은 그림 전체를 평면으로 움직이는 것뿐이다(피사체만 움직이거나 시차를 주는 효과 없음 — AI 움직임 공급자 영역).
- 브라우저 재생은 CI의 e2e(b) 단계 `e2e/video_playback.mjs`가 **Google Chrome(리눅스, 헤드리스)** 에서 확인한다(불러오기·크기·길이·재생 진행·그림 그려짐). 휴대폰, Safari, Firefox, Windows·macOS에서의 재생은 **미확인**.

## 파일 안에 넣는 설명 글
`encode_mp4(..., comment=...)`·`make_mp4(..., comment=...)`는 한 줄(1~500자)을 MP4의 comment 태그에 넣고 `probe_mp4()["comment"]`로 다시 읽는다. AI 표시처럼 **파일과 함께 다녀야 하는 문구**를 넣는 자리다. 어떤 문구를 넣을지는 이 모듈이 정하지 않는다(표시 기준은 `app/ai_marking.py`와 법무 결정).

## 3D 회전 컷 → 회전 영상 (E-08b)
`make_turntable_mp4(cuts, aspect, seconds, turns=1)`은 서버측 렌더(`ai_creator_studio_3d_viewer/scripts/render_glb.mjs --turntable N`)가 만든 360° 그림 묶음(8~360장, 같은 크기)을 물체가 1~3바퀴 도는 MP4로 만든다. 명령줄: `python scripts/turntable_mp4.py <turn_*.png 폴더> out.mp4 [비율] [초] [바퀴]`.
- 컷은 **자르지 않고 전체를 맞춰 넣고** 남는 곳은 컷의 모서리 색(렌더 배경)으로 채운다.
- 컷과 컷 사이 프레임은 **이웃한 두 컷을 섞은 것**이다(새로 렌더한 것이 아님). 컷이 적거나 빨리 돌면 가장자리가 옅게 겹쳐 보인다 — 5초 한 바퀴(120프레임)에 겹침이 없으려면 컷 120장이 필요하다.
- 마지막 프레임이 첫 프레임으로 이어져 반복 재생이 끊기지 않는다.
- 섞인 프레임 수는 `turntable_blended_frames(컷 수, 초, 바퀴)`로 미리 알 수 있고 결과 기록의 `blended_frames`에도 남는다. 5초 한 바퀴는 컷 120장이면 0, 24장이면 96이다. 10초는 240장, 15초는 360장이면 0이다(컷 상한 360).
- CI e2e(b)가 합성 모델(구)을 **120컷**으로 렌더 → MP4(섞인 프레임 0) → Chrome 재생까지 한 번에 확인한다. 실제 작가 모델로는 **미확인**.

## 자막 (E-08c)
`make_mp4(..., subtitles=[{"text", "start", "end"}, ...])`는 자막(최대 20개, 글 120자 이내, 시간은 초)을 화면 아래쪽에 흰 글자·반투명 검은 상자로 **굽는다**(Pillow로 직접 그림, 글자를 ffmpeg에 넘기지 않음). 두 줄까지(넘치면 `SUBTITLE_TOO_LONG`), 시간이 겹치면 `SUBTITLE_OVERLAP`, 글꼴이 못 그리는 글자는 `SUBTITLE_GLYPH_MISSING`, 글꼴이 없으면 `SUBTITLE_FONT_MISSING`. 검사는 프레임을 그리기 전에 끝난다. 글꼴과 라이선스는 `docs/THIRD_PARTY_FONTS.md`. 영상 작업 API의 `subtitles` 필드는 아직 없다.

## 표지 그림
`poster_image(content, at=0.0, max_side=None)`은 영상의 한 프레임을 RGB 그림으로 돌려준다(`at`은 0~1 위치, `max_side`는 긴 변 상한, 확대는 하지 않음). 목록·썸네일처럼 그림만 보일 수 있는 곳에 쓸 표지용이다. 어디에 저장할지는 API 연결 때 정한다.

## 영상 작업 API에 연결하기 전에 정해야 할 것 (코드를 읽어 확인한 사실)
1. **자산 종류가 "그림 아니면 3D 모델" 둘뿐이다.** `app/assets/store.py`·`app/ports/assets.py`는 `media_type`이 `image/`로 시작하지 않으면 `asset_kind`를 `model`로 본다. MP4를 그대로 저장하면 3D 모델로 분류된다 → `video` 종류를 추가해야 한다(저장소·PostgreSQL 쪽 조회 조건 포함, 인가·저장 변경).
2. **AI 표시가 그림에만 들어간다.** `app/ai_marking.py::serve`는 `image/`가 아니면 표시를 넣지 않고 그대로 내보낸다 → 영상은 위 comment 태그를 만들 때 넣는 방식으로 메워야 한다.
3. **mock은 요청 안에서 바로 만든다.** 15초 MP4는 CI 러너에서 약 10초가 걸려 요청 하나가 그만큼 붙잡힌다 → 대기·진행 상태가 있는 작업 방식(작업자)으로 옮길지 결정이 필요하다.
4. 썸네일(`app/image_thumbs.py`)·룩북·사진 단계는 그림만 받으므로 영상 자산은 자동으로 빠진다(오류가 아니라 대상 아님). 영상의 표지 그림은 `poster_image`로 만들 수 있고, 저장 위치는 미정이다.

## 의존성·라이선스 (결정 필요)
- 파이썬 의존성 추가 없음. **ffmpeg 실행 파일**이 서버에 있어야 한다(CI는 Ubuntu 꾸러미를 `apt-get`으로 설치).
- ffmpeg와 H.264 인코더(libx264)의 라이선스 조건, H.264 특허 사용료 해당 여부는 **이 문서에서 확인하지 않았다(미확인)**. 운영 서버에 설치하기 전에 확인이 필요하다 → 사용자·법무 결정 사항.
