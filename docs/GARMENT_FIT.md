# 상의 껍데기 맞춤 (R-ENGINE-03a · 트랙 A 1단계)

`ai_creator_studio_backend_starter/app/garment_fit.py` — 레인 2의 치수 마네킹(`app/mannequin.py`) 둘레에 **상의 껍데기**를 씌워 한 파일(.glb)로 만든다. 순수 파이썬, 사진·AI·외부 호출 없음.

## 되는 것
- `build_fitted_glb(몸 치수, 사이즈표, 사이즈)` → (GLB, 보고). GLB는 노드 0 = 마네킹(`skin`), 노드 1 = 옷 껍데기(`garment`, 양면). 서버측 렌더(`render_glb.mjs`)와 회전 영상 경로에 그대로 들어간다(연결은 R-ENGINE-04).
- 껍데기 둘레는 **사이즈표의 완성 둘레**(엉덩이·허리·가슴·윗가슴 4개 고리). 몸보다 작아서 파고들 자리는 **밖으로 밀어** 피부와 `MIN_GAP_CM`(0.4cm) 이상 띄운다.
- 사이즈가 몸에 **너무 작으면** 숨기지 않고 `cannot_fit`으로 보고하고(껍데기는 파고들지 않게 밀려 있음), 천이 늘어나는 정도(`stretch`)로 닿을 수 있으면 `stretched`.
- 시험은 **완성된 GLB 안의 두 메시**를 읽어 확인한다: 껍데기 삼각형의 변·무게중심 1000여 점이 몸 단면 안에 들어가지 않음, 고리마다 간격 ≥ 최소 간격, 사이즈가 클수록 껍데기가 큼, 같은 입력 → 같은 바이트.

## 안 되는 것 (정직하게)
- **천 시뮬레이션이 아니다.** 늘어짐·주름·접힘이 없는 뻣뻣한 통이다. 소매·목선·밑단 모양 없음. "옷처럼 보이는" 모양이 아니라 **크기 관계를 보는 기준 형상**.
- 몸은 마네킹(통 모양)이지 사람이 아니다. 결과는 마네킹과 같은 "참고용(근사치)" 표시를 단다.
- 하의·여러 옷 종류·사용자 옷 사진·실사 보정(트랙 B)은 이후 단계(R-ENGINE-03b~).
- 브라우저·렌더 화면·API 연결 없음. 실제 사용자 데이터로 검증하지 않았다.
