# 사용자 의류 GLB → garment.v1 후보 (E-15 중 자체 코드 부분)

`app/garment_import.py` — 사용자가 올린 의류 `.glb`를 `garment.v1` 후보로 바꾸는 순수 파이썬 단계(모델·네트워크·새 의존성 없음). **API·화면 연결은 아직 없다**(모듈·시험까지).

## 하는 일
1. **정리**: 씬 그래프의 모든 노드 변환(행렬 또는 이동·회전·스케일)을 꼭짓점에 **굽는다**; 모든 삼각형 프리미티브를 **메시 1개·재질 `base` 1개**로 합친다(첫 재질의 색). **텍스처는 버린다**(garment.v1에 텍스처가 없음 → `texture_dropped`로 알림). 밑단을 y=0에 놓는다.
2. **스케일 추정**: glTF는 미터지만 의류는 cm·mm·인치로 내보내는 일이 흔하다. 키(Y)가 의류로 그럴듯한 **0.25~1.6 m**가 되는 단위를 **모두** 후보로 내고, 둘 이상이면 `ambiguous` — **조용히 고르지 않고** 사람이 확인한 `scale`이 있어야 변환한다(`IMPORT_SCALE_AMBIGUOUS`, 맞는 단위가 없으면 `IMPORT_SCALE_IMPLAUSIBLE`). 가로가 키보다 훨씬 크면 "눕혀졌거나 Z-up일 수 있음" 경고(자동 회전은 하지 않음).
3. **치수 추정**: 종류별 높이(상의: 가슴 70%·허리 30% / 바지: 허리 92%·엉덩이 78% / 치마·원피스 등)의 단면 폭·깊이로 **타원 둘레**. **추정치다**(`estimated: true`): 소매·주름은 값을 키우고 헐렁한 옷은 몸 치수보다 크게 읽힌다 → 사람이 확인·수정. 자체 샘플 상의로 확인: 가슴 81.9 cm(실제 80.2, 약 2%), 허리 67.2(정확). 재킷은 소매 길이를 **받아야** 한다(모양에서 못 구함).
## 권리
**권리 확인이 없으면 결과를 만들지 않는다**: 타사 자산인데 `rights_confirmed`가 아니면 `garments.validate_spec`이 거부한다(시험으로 고정). 이 모듈은 권리를 **판단하지 않는다** — 호출하는 쪽이 업로드 권리 확인 기록을 넘긴다.

## 못 하는 것 (정직하게)
- **몸에 맞춰 변형할 수 없다**: 옷을 몸통·다리·소매로 나누는 분할을 못 하므로 결과에는 `fit` 블록이 없고 `garment_deform`이 거부한다(`fit-ready` 아님). 기준 크기 옷으로만 쓴다.
- 스킨·모프 모델, 삼각형이 아닌 프리미티브, 양자화된 위치, sparse 접근자는 이유를 붙여 거부(`IMPORT_SKINNED`·`IMPORT_UNSUPPORTED`). 삼각형 20만 개 초과 거부.
- 무늬·로고·텍스처 보존, 패턴/봉제선 복원, 사진에서 옷 만들기(R-ENGINE-12 조사)는 범위 밖.
- 실제 사용자 모델로 시험하지 않았다(합성 GLB 17개 시험) — 실제 의류 파일에서의 스케일·치수 정확도는 **미확인**.
