# BUILD-00101 — Job Execution / Output History APIs

## Implementation

- Added authenticated workspace-scoped `GET /v1/generation-jobs/{job_id}/executions` with bounded `limit` and opaque cursor pagination. Attempts are ordered newest-first and expose attempt number, provider/model identifiers, state, request ID, timestamps and error code.
- Cursor tokens encode the last returned attempt number; invalid tokens return HTTP 422. `next_cursor` and `has_more` are returned in response metadata.
- Added authenticated workspace-scoped `GET /v1/generation-jobs/{job_id}/outputs` for persisted Output metadata. The endpoint returns only metadata (output ID, Job ID, MIME type, byte size and creation time); it never exposes private storage keys or file paths.
- Output metadata is returned only after the Job reaches `succeeded`; queued/running/failed Jobs return an empty data list.
- Existing binary Output download remains on the separate authenticated `/output` endpoint.
- Added repository read methods to the Job persistence port and SQLite adapter; wrapped repositories that do not support these reads fail with HTTP 501 rather than silently falling back.

## Boundaries

This is read-only history metadata. It does not generate or alter Jobs, call Providers, create Asset/AssetVersion links, charge credits, or expose private storage keys. SQLite/local filesystem only; PostgreSQL/multi-host and production acceptance are not claimed.
