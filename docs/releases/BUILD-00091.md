# BUILD-00091 — Asset Version Restore

## Scope

Restore a selected immutable historical GLB/GLTF version as a new current version. This build extends BUILD-00090 AssetVersion / AssetRelation / Provenance and adds a version-history action to the existing React/Three.js asset workspace.

## Backend implementation

- `POST /v1/assets/{asset_id}/versions/{version_id}/restore` is available to workspace owner/admin/editor roles.
- The requested historical file must exist inside the configured private asset root, match its recorded byte length and SHA-256, and pass the same GLB/GLTF validation as a new upload.
- Restore creates a fresh unique storage key and a new monotonically increasing version number. It never rewrites or reuses the selected historical file.
- The current Asset pointer, new `asset_versions` row, and `asset.version_restored` provenance event are committed inside a SQLite `BEGIN IMMEDIATE` transaction.
- `GET /versions` now includes `is_current` without exposing private storage keys.
- Missing/corrupt historical bytes fail closed with HTTP 409 and do not change Asset/version metadata. Unknown versions return 404; unauthorized viewer role returns 403.

## Viewer implementation

- AssetWorkspace loads the selected asset's version history.
- Older versions expose a restore action; current version is identified by `is_current` and has no restore button.
- After restore, the asset list, preview URL, and version history are reloaded.

## Boundaries

- SQLite + local filesystem only. The DB transaction does not make the filesystem write crash-atomic; a process crash can leave an orphan artifact, which remains subject to the documented dry-run cleanup workflow.
- PostgreSQL, multi-host concurrency, object storage, live FASHN generation, credit persistence, and G0-G5 remain unverified/unimplemented as previously documented.
