# BUILD-00107 — Immutable AssetVersion Preview and Photo Source Pinning

## Implementation

- Added `POST /v1/assets/{asset_id}/versions/{version_id}/preview-url` and signed `GET /v1/assets/{asset_id}/versions/{version_id}/preview`.
- Version-preview HMAC signs the tuple `(asset_id, version_id, expires)`. URL issuance and file serving verify private path containment, file existence, exact size and SHA-256 against the immutable AssetVersion record. Responses use `Cache-Control: private, no-store` and `X-Content-Type-Options: nosniff`.
- Historical version preview remains bound to v1 after v2 becomes the current Asset version; current-asset preview remains current-version behavior.
- Photo Draft creation/update now snapshots the source `AssetVersion ID` and SHA-256 into the stored draft input. Existing legacy drafts without a snapshot pin the current version at first local run.
- Local Photo run fingerprint includes the pinned source version/checksum. The processor reads and verifies that exact version file, not the mutable current Asset pointer. Same idempotency key replays the same result even if a newer source version is later uploaded.
- Derived Photo Asset provenance and Photo output manifest include the source version/checksum. Derived Asset persistence verifies that the referenced source version still exists and matches the recorded checksum.
- `PhotoDraftWorkspace` previews the exact pinned source and output versions. `OutputReviewWorkspace` previews the exact version under review, not a later current version.
