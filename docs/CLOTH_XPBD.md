# XPBD 천 — 1단계 조사 메모 + 최소 데모 (M3)

`app/cloth_xpbd.py` + `scripts/cloth_demo.py` — **연구용 데모**. 상의 1벌(민소매 통)이 어깨 고리에 고정된 채 중력으로 늘어지고, 몸통(몸 메시와 같은 타원 단면 스택)에 부딪혀 밀려난다. 순수 파이썬(numpy 없음), CPU. **API·화면 연결 없음, 제품 기능 아님.**

## 왜 XPBD인가 (조사 메모)
- **PBD/XPBD**(위치 기반 동역학): 힘 대신 "제약을 만족하도록 위치를 직접 옮김" → 시간 간격·반복 수가 작아도 터지지 않아 실시간·CPU 친화적. XPBD는 제약마다 **컴플라이언스(부드러움)** 를 두어 반복 수·시간 간격과 무관하게 천의 단단함이 일정해지는 PBD의 개량(`Δλ = (−C − α̃λ)/(w_i+w_j+α̃)`, `α̃ = α/Δt²`). 이 데모의 신축(거리)·전단(대각선)·굽힘(두 칸 건너 거리) 제약이 모두 이 형태다.
- **대안**: ① 질량-스프링 + 암시적 적분(안정적이나 큰 선형계 풀이 필요) ② FEM 천(정확, 무겁고 구현 큼) ③ 학습 기반 드레이프(모델·데이터·라이선스 필요, 이 저장소 규칙상 지금은 제외) ④ 지금 방식의 사전 맞춤(`garment_deform`, 정적). 1단계는 ②③을 하지 않고 XPBD로 "가능성과 비용"만 잰다.
- 이 저장소의 제약: numpy/OpenCV 없음 → 순수 파이썬 루프. 

## 데모 설정
격자 24열 × 20행 = **480 입자, 제약 2,760개**(신축·전단·굽힘), 상단 열 24개 고정, 입자 질량 ≈ 면밀도 0.18 kg/m², 1/60 s × 240 스텝(4 s), 스텝당 반복 6회, 속도 감쇠 0.985, 몸과 간격 4 mm. 시작 모양은 몸통 ×1.12에 끝단 10 % 넓은 A라인.

## 측정 (이 개발 PC, 여성 프리셋)
| 항목 | 값 |
|---|---|
| 스텝당 시간 | **23 ms**(240스텝 5.6 s) — 순수 파이썬, 단일 스레드 |
| 몸 안으로 들어간 입자 | **0** |
| 신축 변형률(제약 길이 대비) | 최대 **12.6 %**, 평균 1.4 % |
| 마지막 최대 속도 | 0.0017 m/s (정지에 수렴) |
| 밑단 높이 | 평균 0.785 m, 최저·최고 차 4 mm |

**8 GB급 PC에서의 시간은 미측정**(이 PC 숫자만 있음; 단일 스레드 순수 파이썬이라 메모리는 수 MB로 8 GB가 병목이 아님이 확실하나 속도는 CPU에 비례).  그림: `python ai_creator_studio_backend_starter/scripts/cloth_demo.py out.png`(이전/이후, 앞·옆).

## 비용 추정 (2단계 입력용, 외삽이므로 불확실)
시간은 대략 `입자 × 제약 × 반복 × 스텝`에 비례. 실제 의류 1벌(예 5천~2만 입자, 위 시연의 10~40배)은 순수 파이썬으로 **스텝당 0.2~1 초**, 4초 드레이프에 **수 분~수십 분** → 서버 작업으로는 가능하나 대화형은 불가. 실시간이 목표면 ① numpy 도입(백엔드 의존성 결정 필요) ② C/Rust 확장 ③ GPU가 필요하다(모두 사용자 결정 사항).

## 한계 (정직하게)
- 소매·팔 없음(몸통 타원 스택만 충돌체), **자기 충돌 없음**, 접촉 마찰은 속도 감쇠뿐, 봉제선·직물 방향성·주름 방향 없음.
- 최대 신축 12.6 %는 고정 고리 바로 아래 제약의 집중으로 보이며 "얇은 직물"로는 큼(반복 수·컴플라이언스 조정 여지, 미튜닝).
- 시작 모양이 이미 몸에 가까워 이전/이후 차이가 작다(그림 확인) — 큰 드레이프(어깨에서 떨어뜨리기 등)는 시험하지 않았다.
- 실제 `garment.v1` 메시를 입력으로 쓰지 않았다(별도 격자). 연결하려면 의류 메시의 위상(고정점·분할) 처리가 필요 — 2단계 과제.
- 매개변수(질량, 컴플라이언스, 반복 수)는 눈으로 맞춘 **제안값**.
