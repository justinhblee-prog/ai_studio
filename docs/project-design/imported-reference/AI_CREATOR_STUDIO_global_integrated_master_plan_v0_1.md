## 0. 이번 재설계의 결론

AI CREATOR STUDIO는 특정 이미지 생성 모델의 UI가 아니라, 개인 창작자와 기업이 캐릭터·상품·브랜드 자산을 기반으로 이미지·3D·영상 콘텐츠를 제작하고, 팀 업무로 운영하며, 장기적으로 에셋을 유통·라이선스할 수 있는 글로벌 크리에이티브 플랫폼을 지향한다.

단, 첫 시장 진입은 모든 기능과 모든 고객을 동시에 공략하지 않는다.

- **장기 플랫폼 방향:** 글로벌 크리에이터 플랫폼
- **초기 수익화 방향:** 패션·의류·이커머스 B2B 제작 워크플로
- **초기 검증 제품:** 고객의 상품/브랜드 자산에서 시작하는 반복 가능한 이미지·룩북 제작 업무
- **초기 기술 검증:** 실제 3D Viewer 실행 + 실제 이미지 기반 AI Try-on 공급자 호출 + 공통 Project/Asset/Job/Output 흐름
- **후속 확장:** 사진형 2D 품질 파이프라인, 영상, 3D 의상 시뮬레이션, Marketplace, 산업별 플러그인

글로벌 우선은 첫날부터 모든 국가에 영업비와 광고비를 쓰겠다는 뜻이 아니다. 제품·브랜드·데이터 구조는 글로벌 기준으로 만들고, 국가별 판매와 지원은 검증 결과에 따라 단계적으로 확장한다.

## 1. 사업 비전과 포트폴리오

### 1.1 사업 정의

AI CREATOR STUDIO는 캐릭터, 상품, 브랜드, 3D 에셋을 출발점으로 AI 기반 비주얼 콘텐츠를 제작하고, 제작 결과·버전·비용·권리·승인 과정을 통합 관리하는 글로벌 크리에이티브 플랫폼이다.

### 1.2 3개 사업 축

| 축 | 목적 | 핵심 사용자 | 장기 기능 |
|---|---|---|---|
| Studio | 제작 도구 | 개인 크리에이터, 디자이너, 브랜드 제작자 | Character Studio, 3D Studio, Try-on, Photo, Video |
| Business | 반복 제작 운영 | 브랜드, 이커머스, 에이전시, 제조·유통사 | Workspace, 프로젝트/SKU, 브랜드 정책, 검수·승인, 대량 작업, API |
| Marketplace | 에셋 거래·라이선스 | 크리에이터, 구매자, 기업, 에이전시 | 캐릭터·모델·프리셋·템플릿·3D 에셋·콘텐츠 판매 및 라이선스 |

세 축은 별도 제품처럼 보일 수 있지만 공통으로 Asset, Version, Project, Rights/License, Payment/Credit, Review, Identity/Workspace를 공유하는 구조를 목표로 한다.

### 1.3 첫 진입시장과 장기 확장

- 초기 진입: 패션·의류·이커머스의 상품 이미지, 가상착장, 룩북, 캠페인 콘텐츠.
- 고객 우선순위 가설: 온라인 셀러/D2C 브랜드 → 인하우스 브랜드팀 → 콘텐츠 제작 대행사 → 제조·유통사.
- 장기 확장: 뷰티, 식품, 리빙, 여행, 부동산 등. 각 업종은 공통 코어를 재사용하되 별도 업무 플러그인과 품질 기준을 갖춘다.
- B2C는 장기적으로 중요하지만 초기 B2B 업무 흐름을 복잡하게 만들지 않도록 별도 온보딩·요금·권한 경로로 설계한다.

## 2. 시장·고객 전략

### 2.1 고객 문제 가설

1. 촬영·모델·스튜디오·후보정 비용과 일정 부담.
2. 생성 결과에서 상품의 색상·패턴·실루엣·로고가 달라지는 문제.
3. 여러 AI 서비스 사이에 원본·프롬프트·버전·결과가 흩어지는 문제.
4. 재시도·실패·크레딧 차감·실제 비용이 불투명한 문제.
5. 팀의 브랜드 기준·검수·승인·납품 상태를 통제하기 어려운 문제.
6. 고객 이미지와 인물 데이터가 외부 공급자에게 어떻게 전송·보관되는지 불명확한 문제.

위 항목은 고객 인터뷰와 파일럿으로 확인할 가설이며, 시장 전체의 확정 사실로 표현하지 않는다.

### 2.2 고객 조사 프로그램

- 목표 인터뷰: 초기 15~30개 기업(내부 실행 목표, 시장 통계 아님).
- 목표 유료 파일럿: 3~5개 기업(초기 검증 목표).
- 인터뷰 대상: 쇼핑몰 운영자, 브랜드 마케팅/이커머스 담당자, 제작 대행사, 의류 제조·유통사.
- 확인 질문: 현재 제작 공정, 월 SKU/콘텐츠 수, 외주·촬영 비용, 재작업 원인, 승인 흐름, 데이터/권리 우려, 예산 승인자, 구매 기준.
- 실험: 동일 원본과 동일 조건으로 결과 비교. 고객이 실제 승인·게시한 비율과 작업당 총원가를 기록.

### 2.3 국가 선정 원칙

글로벌 진출 후보 국가의 순위는 확정하지 않는다. 기존 글로벌 전략서의 미국·캐나다, 일본, 영국·유럽, 싱가포르·동남아시아, 중국 별도 검토는 초기 가설로 유지하되, 다음 점수표로 재평가한다.

| 평가 항목 | 판단 기준 |
|---|---|
| 문제 강도 | 패션 콘텐츠 제작 빈도와 외주/촬영 부담 |
| 구매 가능성 | B2B 예산, 의사결정 속도, 파일럿 계약 가능성 |
| 제품 적합성 | 현지 상품 이미지/언어/워크플로와 기능 적합성 |
| 접근성 | 파트너·리드 확보·광고·커뮤니티 접근 |
| 결제 가능성 | 법인 자격, 해외 카드, 구독·사용량 과금, 환불·세금 |
| 규제·권리 | 개인정보, AI 투명성, 초상권, 저작권, 데이터 이전 |
| 운영 비용 | 현지화, 고객지원, 법무, 세금, 정산 비용 |
| 경제성 | CAC, 파일럿 전환율, ARPA, 유지율, 공헌이익 |

**결정 원칙:** 글로벌 제품 기반은 처음부터 준비하되, 국가별 영업 확대는 실제 고객 인터뷰·유료 파일럿·CAC·유지율·지원 비용을 확인한 뒤 결정한다. 중국은 플랫폼·규제·결제·데이터 정책이 달라 별도 조사 트랙으로 둔다.

## 3. 제품 전략과 경험 설계

### 3.1 제품의 공통 사용자 흐름

**Discover → Create → Review → Manage → Publish/Trade**

1. Discover: 기능·샘플·템플릿·마켓 에셋 발견.
2. Create: 프로젝트 생성, 원본/에셋 선택, 목적·제약 설정, 엔진 선택.
3. Review: 결과 비교, 품질 검토, 재생성/수정, 승인.
4. Manage: 자산·버전·권리·비용·팀 작업 관리.
5. Publish/Trade: 다운로드·채널 내보내기·공유·라이선스 거래.

### 3.2 Studio 제품군

- Character Studio: 캐릭터 프로필, 얼굴/헤어/체형/피부/의상/포즈 속성, 참조 이미지, 정체성 버전 관리.
- 3D Studio: GLB/glTF 로드, 회전·줌, 정면/측면/후면, 카메라·조명·재질·배경, 씬 저장/복원.
- Try-on Engine: 사람 참조 이미지 + 의류 이미지 기반의 외부 AI 가상착장.
- Photo Studio: 이미지 기반 결과의 사진형 2D 보정·후처리·내보내기.
- Video Studio: 프레임 간 일관성을 다루는 별도 시간축 생성 파이프라인. 초기 실구현 후순위.
- Lookbook/Campaign workflow: 여러 상품·모델·씬 결과를 컬렉션 단위로 묶고 검수·납품.

### 3.3 Business 제품군

- Organization / Workspace / Membership / RBAC
- Project / SKU / Asset / Asset Version / Brand Kit
- 작업 견적 / Job / Job Event / Result / Review / Approval
- 팀 공유, 승인 단계, 내보내기, 고객별 프로젝트 분리
- 사용량·비용·크레딧 원장·예산 한도
- 기업용 정책, 데이터 보존/삭제, 감사 이력, API 및 대량 작업(수요 검증 후)

### 3.4 Marketplace 제품군

Marketplace는 장기 비전의 핵심이지만, 권리·정산·분쟁 체계가 갖춰지기 전에는 거래 기능을 공개하지 않는다.

- 카탈로그 A: Creator-to-Creator — 프롬프트, 프리셋, 템플릿, 캐릭터, 모델, 3D 에셋, 완성 콘텐츠.
- 카탈로그 B: Business/Brand — 검증된 모델, 브랜드 승인 에셋, 의상 템플릿, 캠페인 키트, 에이전시 서비스.
- 공통 기반: 판매자 확인, 권리 선언/증빙, 라이선스 범위, 에셋 버전, 구매 이력, 결제·정산, 신고·삭제·분쟁·환불.
- 라이선스 필드: 개인/상업 이용, 수정, 재배포, 재판매, 독점 여부, 기간, 지역, 좌석/사용량.
- 구매 에셋은 사용자의 Workspace에 들어가 Studio 도구에서 직접 사용할 수 있어야 한다.
- AI 생성물이라는 사실만으로 독점 저작권 또는 재판매 권리가 보장되지 않는다.

## 4. 기술 설계 기준

### 4.1 파이프라인 분리

| 파이프라인 | 입력/출력 | 구분 및 주의 |
|---|---|---|
| 3D Viewer / Scene Editor | GLB/glTF → 인터랙티브 씬 | 메시 표시·카메라·조명 제어. 의상 자동 피팅 아님 |
| 3D Garment Simulation | 의상 메시 + 인체 리깅/포즈 → 변형된 3D 착장 | 별도 기술·자산·물리/충돌·핏 검증 필요 |
| Image-based AI Try-on | 사람 이미지 + 의류 이미지 → 2D 착장 결과 | 3D 메시 착용과 다른 AI 파이프라인 |
| Photorealistic 2D Photo Engine | 이미지/승인 결과 → 보정된 사진형 결과 | 3D 뷰포트 캡처와 동일시 금지 |
| Video Pipeline | 이미지/씬/프롬프트 + 시간축 → 영상 | 프레임 간 인물·의상·로고 일관성 별도 검증 |

### 4.2 공통 아키텍처 원칙

- 후보 스택: Next.js/React/TypeScript, Python/FastAPI/Pydantic, PostgreSQL, 관리형 Queue 또는 Redis Queue + Worker, S3 호환 비공개 스토리지/CDN, 관리형 인증/OIDC, Secret Manager/KMS, 구조화 로그/OpenTelemetry.
- 시작 구조: 모듈러 모놀리스 + API/Worker 분리 배포. 초기 Kubernetes와 과도한 마이크로서비스는 피한다.
- 핵심 모듈: Identity/Tenant, Workspace, Asset, Project, Engine Hub, Generation/Jobs, Billing/Ledger, Review, Audit/Operations.
- Provider Adapter: validate_request, estimate_cost, submit_job, poll_or_webhook, cancel_if_supported, normalize_result, map_error.
- 라우팅: Capability/입력/테넌트/지역/권리/예산의 하드 필터 → 정책 필터 → 품질·비용·지연·성공률 점수.
- AUTO fallback만 명시 정책에서 허용. MANUAL 선택은 조용히 다른 공급자로 바꾸지 않는다.
- Job은 비동기 상태 머신, 멱등성, 재시도, 취소, 결과 영속화, 중복 과금 방지를 갖춘다.
- Credit Ledger는 append-only RESERVE/CAPTURE/RELEASE/REFUND/ADJUST 이벤트로 관리한다.
- 원본 Asset은 불변으로 두고 파생 결과는 별도 Asset/Version으로 기록한다.
- 테넌트 격리, 서버 측 권한검사, 업로드 검증, 비밀키 보호, 데이터 삭제·보존 정책을 기본 설계에 포함한다.

### 4.3 아직 확정하지 않을 기술 항목

- API prefix `/v1` vs `/api/v1`
- 기존 코드의 실제 DB 스키마와 Organization/Membership 누락 여부
- Asset 소유권·공유 관계·Character Identity Profile 구조
- Job 상태/이벤트/재시도 계약
- 기존 Three.js 코드와 GLB 실행 가능성
- 실제 Try-on Provider 및 상업 이용·보존·학습·삭제 약관
- 한국 법인 기준 글로벌 결제 사업자/정산 가능성
- 실제 비용·성능·품질 수치

이 항목은 저장소, 실행 로그, 공급자 약관·계정, 실측 데이터가 확보된 후 대표 승인과 개발자 검토로 확정한다.

### 5.2 UX 원칙

- 첫 화면에서 고객의 목적을 먼저 묻고, 전문가 설정은 단계적으로 노출한다.
- 초보자는 가이드형 흐름, 전문가는 세부 제어·프롬프트·엔진·파라미터 접근.
- 고객 자산으로 시작하는 B2B 흐름을 기본으로 하되, 캐릭터부터 시작하는 Creator 경로도 유지.
- 실행 전에 예상 비용, 선택된 엔진, 제약, 데이터 처리 요약을 보여준다.
- 결과 화면은 원본/결과 비교, 버전, 실패 사유, 품질 검수, 승인 상태를 중심으로 구성한다.
- 생성 기능을 실제 연결하기 전에는 Mock/미리보기임을 명시한다.
- 웹사이트 구현은 별도 지시 전까지 재개하지 않는다. 이번 단계는 IA와 UX 기준 정리다.

### 6.4 영업 퍼널

리드 발굴 → 문제 인터뷰 → 고객 샘플 진단 → 데모 → 범위·KPI 합의 → 권리/보안 확인 → 유료 파일럿 → 결과 리뷰 → 구독/기업 계약 → 온보딩/정기 성과 리뷰.

초기 영업은 대규모 광고보다 대표자 직접 영업과 파트너를 통한 파일럿 확보를 우선한다. 기존 마케팅 계획의 주간 접촉량·상담량 목표는 실행 가설로 보관하고, 실제 전환율로 조정한다.

### 6.5 초기 콘텐츠와 랜딩 구조

- 영어 글로벌 랜딩을 기본으로 설계하고 한국어·일본어 현지화 구조를 준비한다.
- 전용 페이지: Fashion AI Lookbook, AI Virtual Try-on, AI Product Photography, 3D Character/Scene Studio, Business Workflow.
- 페이지에는 문제, 입력/출력, 실제 작동 영상, 한계/지원 조건, 고객 사례, CTA를 포함한다.
- 제품이 아직 구현되지 않은 기능은 “Coming soon” 또는 개발 로드맵으로 표시하고 현재 기능처럼 광고하지 않는다.
- SEO는 번역량보다 국가별 검색 의도·구매 의도·실제 사례에 맞춘다.
- 유료 광고는 랜딩 전환과 사례 데이터가 확보된 뒤 소액 실험한다.

### 6.6 마케팅 KPI

- Acquisition: 적격 리드, 국가별 리드, 상담 예약, 유입 채널.
- Activation: 가입 후 첫 성공 결과까지 시간, 첫 프로젝트 완료율.
- Quality: 상품 충실도, 승인 가능한 결과 비율.
- Conversion: 상담→데모→파일럿→유료 계약 전환율.
- Economics: CAC, ARPA, 작업당 원가, 공헌이익, 회수 기간.
- Retention: 기업 유지율, 월간 사용량, 반복 작업률.
- Trust: 권리 신고, 삭제 요청, 보안 사고, 환불·분쟁.

## 7. 가격·수익 모델

수익원 후보:
1. Team/Business 구독 + 포함 크레딧 + 초과 사용량.
2. 작업별 사용량 과금.
3. Enterprise 계약(API, 대량 처리, 정책, 지원/SLA).
4. 온보딩·브랜드 키트·워크플로 설정 등 서비스.
5. Marketplace 판매 수수료/라이선스 수익(후속).

기존 월 정액·무제한·Face-Lock·4K 등의 수치는 실측 원가·품질·권리 검증 전 가격표나 광고 약속으로 확정하지 않는다.

가격 산식:
`고객 판매가격 = (공급자 원가 + 재시도 기대원가 + 저장/전송 + 결제 수수료 + 지원/운영 배부원가) ÷ (1 - 목표 공헌이익률)`

파일럿은 특정 업무·기간·작업량·지원 범위·KPI를 계약에 명시한다. 무료 체험은 비용 한도와 기능 제한을 둔다.

## 8. 글로벌 운영·법무·신뢰

출시 국가별로 다음을 검토한다.
- 개인정보 처리자/수탁자 역할, 개인정보 보호, 데이터 보관·삭제·국외 이전.
- AI 생성물 표시·투명성, 광고 표현과 소비자 오인 방지.
- 저작권·상표권·초상권·퍼블리시티권 및 업로드 자료 사용 허락.
- 공급자별 입력 보존·학습 이용·처리 지역·하위 처리자·삭제 조건.
- 결제·구독·사용량 과금·세금·환불·분쟁.
- Marketplace 판매자 확인·권리 증빙·라이선스·정산·세금·신고/삭제.
- 접근 통제, 관리자 MFA, 감사 로그, 백업/복구, 사고 대응.

한국·미국·EU·일본·중국 등 국가별 법률은 전문가 검토가 필요하다. 본 문서는 법률 자문이 아니다. 글로벌 진출을 이유로 모든 국가의 규제를 한 번에 완전히 충족했다고 주장하지 않는다.

## 9. 로드맵과 Gate

### Stage 0 — 재설계 기준선/실사
- 기존 문서·디자인·저장소·코드·테스트·API 계정 상태 감사.
- 글로벌 통합 기준서 승인.
- 고객 인터뷰 대상과 테스트 자산 권리 확보.
- 개발자 주간 투입량, 기술 스택, 예산 상한, API 접근 확인.

### Stage 1 — 핵심 기술·고객 PoC
- 3D Viewer: GLB 3종 이상, 회전/줌/뷰 프리셋, 씬 저장/복원, 오류 처리.
- AI Try-on: 실제 Provider 1개 이상 호출, 성공/실패/시간/원가 기록, 권리 조건 확인.
- 동일 테스트셋으로 품질 평가.
- 첫 고객 업무 한 가지에 대한 유료 파일럿 적합성 검증.

### Stage 2 — 핵심 업무 수직 통합
- 로그인/Workspace → Project/Asset 업로드 → 견적/예약 → Job → Provider → 결과 저장 → 검수/승인 → 원장 확정/환급 → 다운로드.
- 권한, 멱등성, 재시도, 삭제, tenant isolation 테스트.
- Photo Engine 최소 파이프라인 검증.

### Stage 3 — B2B 유료 베타
- 팀·브랜드 정책·SKU/배치·사용량 과금.
- 고객 3~5곳 반복 사용 및 고객 승인 결과.
- 실측 원가/공헌이익/지원 비용 확인.
- 국가별 결제·약관·데이터 정책 준비.

### Stage 4 — 글로벌 성장/확장
- 성과 국가에 현지화·영업·광고 확대.
- Creator Studio 고도화.
- Video 및 3D Garment Simulation 별도 PoC.
- Marketplace는 권리·정산·분쟁·세금 체계가 통과한 후 단계적 공개.

### 필수 Gate
- G0: 기존 산출물·저장소 감사 완료.
- G1: 실제 3D Viewer 실행 증거.
- G2: 실제 Provider API 호출과 결과·원가·권리 증거.
- G3: 공통 업무 흐름과 보안/원장 통합 테스트.
- G4: 고객이 승인·반복 사용한 파일럿 증거.
- G5: 국가별 법무·결제·지원 준비 후 해당 국가 출시.

Gate 통과 전에는 다음 단계 완료를 선언하지 않는다.

## 10. 책임과 협업 운영

| 주체 | 책임 | 승인/증거 |
|---|---|---|
| 제품 책임자(사용자) | 비전, 시장, 우선순위, 예산, 정책, 최종 승인 | 주요 범위·가격·국가·법률/데이터 정책 승인 |
| 개발자(Technical Lead/Implementation Owner) | 기술 타당성, 저장소 감사, 아키텍처 공동 설계, 코드·API·인프라·테스트·배포 | PR/커밋, 실행 로그, 테스트 결과, 배포/운영 증거 |
| ChatGPT(통합 PM/BA/QA 지원) | 문서 기준선, 요구사항 추적, 충돌 분석, 명세 초안, 개발 결과 검토, QA·마케팅 계획 정합성 | 문서·검토표·테스트 체크리스트, 검증된 근거 인용 |

모든 작업은 Owner, Contributors, Approver, Input, Output, Acceptance Criteria, Dependencies, Status, Evidence를 가진다. 기술 설계는 개발자와 공동 작성하며 ChatGPT가 개발자의 기술 결정을 일방적으로 대체하지 않는다.
