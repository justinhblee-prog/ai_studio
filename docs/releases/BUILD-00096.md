# BUILD-00096 — Product / SKU Catalog

## Implementation

- Added workspace-scoped Product catalog with SKU, name, description, category, status, creator/timestamps and ordered image Asset associations (`primary` / `gallery`). Each Product requires 1..12 active same-workspace image assets.
- SKU is normalized to uppercase and unique case-insensitively within a Workspace. Duplicate SKU returns HTTP 409.
- Added create/list/read/update/archive/event-history APIs. Product lists and event history use bounded pagination.
- Active Products protect their referenced images from deletion. Product archive is non-destructive and releases this active image protection.
- Lookbook Draft now accepts `product_ids` and/or direct `product_asset_ids`. Catalog Products must be active and have active images; image references are snapshotted into `lookbook_draft_assets`.
- Active Lookbook Drafts protect catalog Products from archive. Archive the Lookbook Draft first; draft and event history remain retained.
- Added `ProductCatalogWorkspace` UI to register SKUs and image assets, and extended `LookbookDraftWorkspace` to select multiple catalog Products.
- Migrated legacy `lookbook_draft_entities` constraint to allow `product` references while preserving existing project/character rows. Migration runs in a SQLite write transaction.

## Explicit exclusions

- Product variants (size/color/fit), SKU hierarchy, external marketplace sync, pricing, inventory and barcode remain unimplemented.
- Product edit UI is API-capable but the current ProductCatalogWorkspace UI focuses on create/archive.
- Lookbook remains preparation-only: no generation, review/approval, export or credits.
