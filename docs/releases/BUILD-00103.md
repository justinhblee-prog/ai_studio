# BUILD-00103 — Failed Output Asset Link Retry / Audit

## Implementation

- Added owner/admin-only `POST /v1/generation-jobs/{job_id}/outputs/{output_id}/asset-link-retry`.
- Retry requires a non-empty reason (max 2,000 chars), and only `failed` link tasks can be retried. Missing links return 404; pending/processing/linked tasks return 409; editor/viewer roles are denied.
- A retry atomically changes the task back to `pending`, resets the attempt counter, clears lease/error state and appends an immutable `output_asset_link.retry_requested` event.
- Event details retain the retry reason, previous failure and prior attempt count. Added owner/admin-only `GET .../asset-link-events` for the audit history.
- Retry uses the existing deterministic Asset/Version/Provenance IDs and worker path, so it remains safe if a prior attempt committed the Asset DB but failed to acknowledge the Generation DB.
- Added schema migration version 8 and the `generation_output_asset_link_events` table.

## Boundaries

Manual retry is an administrative recovery operation, not a fix for corrupt source data. The operator must restore or correct the private Output file/storage/metadata before retrying. No Provider call or credit charge is performed. SQLite/local filesystem only; PostgreSQL/multi-host/production acceptance remain unverified.
