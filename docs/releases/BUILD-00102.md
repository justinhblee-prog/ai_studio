# BUILD-00102 — Generation Output → Asset/Version/Provenance Linker

## Implementation

- Added `generation_output_asset_links` durable outbox table in the Generation DB. Successful Output finalization inserts its link task in the same transaction as Output, Job success, Execution, Event and Poll Task completion.
- Added `checksum_sha256` to `generation_outputs` with a migration for existing databases. The Provider poll worker calculates and persists the SHA-256 digest of the downloaded private image. Schema migration backfills only succeeded legacy Outputs whose filenames follow the safe attempt-scoped resolver pattern; unsupported legacy names remain `not_queued` for reconciliation.
- Added independent `python -m app.output_asset_link_worker` process and SQLite repository with lease-based claims, bounded retries, and lease-fenced acknowledgement.
- The linker validates the stored image bytes/MIME/size, copies to private Asset storage using an immutable deterministic storage key, and creates a Workspace Asset, immutable AssetVersion v1 and `asset.generated_output_imported` Provenance record.
- Asset IDs, Version IDs and Provenance IDs are deterministic per Output. If Asset DB commit succeeds but Generation DB acknowledgement is lost, a retry verifies and reuses the same Asset instead of duplicating it.
- This recovery protocol works when Generation DB and Asset DB are configured as separate SQLite files. It does not claim a cross-database atomic transaction.
- Output history now includes checksum, Asset/Version/Provenance IDs and `asset_link_status` (`pending`, `processing`, `linked`, `failed`, or `not_queued`). Private storage keys remain hidden. Diagnostics/event payloads also redact storage keys.
- Job diagnostics now redact storage keys from both Output metadata and event payloads.
- Persisted generated-output Assets are protected from ordinary Asset deletion until an explicit Output retention/detachment workflow exists.
- Added `output_asset_link` worker heartbeat to the required worker set and deployment instructions.

## Recovery behavior

1. Poll Worker downloads and validates Provider image, then commits Output + link outbox task.
2. Output Asset Link Worker claims the task under a lease.
3. It validates and copies bytes to deterministic Asset storage, then commits Asset + AssetVersion + Provenance in the Asset DB.
4. Only after that commit does it mark the Generation DB outbox task `linked` under the still-valid lease.
5. If the process crashes between steps 3 and 4, the next worker verifies the deterministic Asset and completes the outbox acknowledgement without creating duplicates.
6. Permanent validation/metadata conflicts fail the task immediately; transient failures retry up to the configured attempt limit. A failed-task manual retry console is not yet implemented.
