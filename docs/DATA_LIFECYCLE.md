# 데이터 수명주기 — 내보내기·삭제·보관 (R-065)

## 1. 흐름 한눈에
| 단계 | 어디서 | 상태 |
|---|---|---|
| ① 내 데이터 내보내기(작업공간) | `POST /v1/workspaces/{id}/exports`(**소유자·관리자**) → `GET /v1/exports/{export_id}/download` | **이번에 구현** |
| ① 내 데이터 내보내기(계정) | `POST /v1/me/exports` → 같은 download | **이번에 구현** |
| ② 삭제 요청 | `POST /v1/me/deletion-requests`(`scope=workspace_content`는 소유자, `account`는 본인) | **이미 있음**(L-01) |
| ② 유예 중 복구 | `DELETE /v1/me/deletion-requests/{id}` — 취소하면 **유예가 지나도 처리되지 않음**(시험) | **이미 있음**(이번에 시험 추가) |
| ② 유예 후 실삭제 | **서버가 자동으로 지우지 않음**: 운영자가 `scripts/purge_requests.py --apply --confirm <요청 ID>`로 실행(R-052 권고: 되돌릴 수 없는 삭제를 웹에서 누르게 하지 않음) | **이미 있음**(이번에 새 표 대응 추가) |
| ④ 삭제·내보내기 감사 | 표 `data_lifecycle_audit`(추가 전용, **삭제 뒤에도 남음**) | **이번에 구현** |

## 2. 설정값(기본값 — **보관·유예 기간은 [결정 필요: 법무]**)
| 설정 | 기본 | 의미 |
|---|---|---|
| `PURGE_GRACE_DAYS` / `--grace-days` | **7일** | 삭제 요청 후 실삭제까지 유예(그 안에는 처리 안 됨, 복구 가능). 임시값 — 법무가 정함 |
| `EXPORT_TTL_HOURS` | **24시간** | 내보내기 파일 보관 시간. 지나면 파일을 지우고 링크는 410 |
| `EXPORT_MAX_BYTES` | **200MB** | 한 번에 내보낼 수 있는 원본 파일 합계(초과 413, 나눠서 내보내기는 지원 요청) |
| `EXPORT_DAILY_LIMIT_PER_WORKSPACE` | **3회/일** | 작업공간(계정 내보내기는 사용자)별 — 초과 429 + `Retry-After` |
| 감사 기록 보관 | **무기한(지우는 코드 없음)** | 이름·ID·파일명·내용이 없고 **해시와 개수만** 있어 남겨도 개인정보가 남지 않음. 기간은 법무 결정 |

## 3. 내보내기 ZIP 내용
**작업공간 내보내기**: `manifest.json`(무엇이 들어 있고 **무엇이 빠졌는지**) + `data/<표>.json`(작업공간 ID가 있는 모든 표의 행: 자산·라이브러리·검수·설정·마켓 항목·프로젝트·상품·캐릭터·작업·구성원 등) + `assets/<자산ID>.<확장자>`(살아 있는 자산의 **저장된 원본 파일 그대로, 해시 포함** — 사진 속 GPS도 그대로: 소유자 본인의 파일).
- **제외(매니페스트에 명시)**: 작업공간 ID 열이 없는 표(`not_included_tables`), **신고로 보류 중인 자산**(목록만, `held_assets_not_included`), 표시용 축소본(원본에서 다시 만들 수 있음), **다른 계정의 개인 데이터**(동의·프로필), 내부 큐·하트비트·알림 표.
- 파일 경로·서명 같은 내부 열(`storage_key` 등)은 뺌.
**계정 내보내기**: 본인 기록만 — 소속 작업공간과 역할, 동의·약관 수락, 삭제 요청, 마켓 프로필·내가 만든 항목·내가 한 신고, 내가 요청한 검수. **작업공간 안의 내용은 포함하지 않음**(소유한 작업공간을 각각 내보내라고 매니페스트가 알려 줌). 이름·이메일은 로그인 서비스가 가지고 있어 이 서버에는 없음.
**접근**: 작업공간 내보내기는 소유자·관리자(요청자가 강등되면 못 받음), 계정 내보내기는 본인만. 남의 것은 "없음(404)"과 같은 응답. 내려받을 때마다 체크섬·크기 검사.

## 4. 파생물 처리표 (삭제하면 무엇이 같이 지워지나)
| 파생물 | 만들어지는 곳 | 작업공간 내용 삭제(`workspace_content`) | 계정 삭제(`account`) |
|---|---|---|---|
| 표시용 축소본 480/960 WebP (R-061) | `private_assets/thumbs/` | **원본 자산과 같이 파일 삭제**(이번에 추가, 시험) | 단독 소유 작업공간이면 같이 삭제 |
| 내보내기 ZIP 파일·기록 | `private_assets/exports/`, 표 `data_exports` / `account_exports` | 작업공간 내보내기 **파일·기록 삭제**(시험) | 계정 내보내기 파일·기록 삭제(시험), 작업공간 내보내기의 요청자 표시는 익명화 |
| 생성 결과·라이브러리 항목(결과 저장) | 자산·`workspace_library_items` | 삭제 | 단독이면 삭제, 공유 작업공간이면 작성자만 `deleted-user`로 익명화 |
| 속성(`attrs`)·검수 기록·검수 이력·작업공간 설정·설정 이력 | R-058·R-063 표 | 삭제 | 사람 열(`requested_by`·`handled_by`·`updated_by`·행위자)은 **익명화**(이번에 추가) |
| 마켓 항목·신고 | `market_listings`, `market_reports` | 항목과 그 항목에 대한 신고 삭제(신고가 항목 삭제로 사라지는 점 주의) | 신고자·권리 확인자 익명화 |
| 마켓 판매자 프로필 | `market_profiles` | (계정 단위 표라 영향 없음) | **삭제** |
| 고객·계약·유입 기록(R-057) | `company_profiles`, `company_profile_history` | 삭제 — ⚠ **계약·해지 기록의 보관 의무가 있는지 법무 확인 필요**(있다면 이 표를 삭제 대상에서 빼야 함) | 같음 |
| 감사 일부 | `asset_review_events`, `download_audit`, `asset_provenance` | 작업공간 것은 삭제 | **행위자만 익명화**(기록은 남음) |
| **삭제·내보내기 자체의 기록** | `data_lifecycle_audit` | **남김** | **남김** |
| 백업 | 백업 도구 | ⚠ **백업에서의 삭제는 이 도구의 범위 밖** — 백업 보관 기간 정책 필요(NEED_USER) | 같음 |
| 외부 공급자에 이미 보낸 사진 | 공급자 서버 | ⚠ **서버가 지울 수 없음** — 공급자 정책·고지 문구(법무) | 같음 |

**추가 전용 이력 표와 삭제**: 이력 표(검수 이력·계약 이력·설정 이력 등)는 앱이 수정·삭제하지 못하도록 DB 트리거가 막고 있습니다. **승인된 삭제 스크립트만** 한 트랜잭션 안에서 그 트리거를 잠시 풀고 지운 뒤 다시 걸고 커밋합니다(실패하면 전부 되돌려 트리거도 그대로). 이 처리가 없던 때는 이력이 있는 작업공간의 삭제가 **중단**되었을 것입니다(이번에 시험으로 확인).

## 5. 삭제 후 확인
- 삭제된 자산·항목·검수·표시 이미지 주소는 **404**(시험). 삭제 스크립트는 **외래 키 검사가 깨끗**한지 시험으로 확인.
- 새 표를 추가하면 삭제 스크립트가 **"UNMAPPED_TABLE"로 중단(안전하게 실패)** 합니다 — 이번에 마켓 신고 표가 이 규칙에 걸릴 상태였던 것을 찾아 고쳤습니다(아래 보고 참고). `tests/test_data_lifecycle.py`가 새 기능 표들이 계속 매핑되어 있는지 확인합니다.

## 6. 결정 필요(법무·사용자)
유예 기간(7일 임시), 내보내기 보관(24시간 임시)·크기 상한, 감사 기록 보관 기간, 계약·해지 기록의 삭제 제외 여부, 백업에서의 삭제 정책, 외부 공급자에 보낸 데이터의 처리 안내 문구, 계정 삭제 시 **공유 작업공간에 남는 내용**(현재: 작성자만 익명화) 정책.
