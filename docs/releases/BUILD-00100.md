# BUILD-00100 — Lookbook Planning Review / Approval

## Implementation

- Added a persistent Lookbook planning workflow: `DRAFT → IN_REVIEW → APPROVED` or `IN_REVIEW → CHANGES_REQUESTED → IN_REVIEW`.
- Added `POST /v1/lookbook-drafts/{draft_id}/submit`, `/approve`, and `/request-changes`; added `GET .../manifest` for approved plan-only manifests.
- Workspace owners/admins can approve or request changes. Owners/admins/editors can submit. Viewers are read-only.
- A non-empty comment is required for change requests. Review actions and comments are appended to the existing event history.
- Draft edits are allowed only in DRAFT or CHANGES_REQUESTED. IN_REVIEW and APPROVED drafts are locked against changes. Re-submission clears the current decision fields while preserving earlier event history.
- Existing draft rows migrate to `workflow_status=DRAFT`; review metadata columns and an index are added transactionally.
- Approved manifest explicitly declares `manifest_type=LOOKBOOK_PLAN_ONLY` and `generated_outputs_included=false`; it contains planning input and referenced asset IDs only, not image files or generated outputs.
- Extended `LookbookDraftWorkspace` with submit, approve, request-changes and manifest inspection actions.
