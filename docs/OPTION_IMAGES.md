# 옵션·도감 이미지 정적 자산 규칙 (R-051)

홈페이지(설계 창 정적 사이트, 배포 위치 `public/site/` 예정 — R-025 결정 대기)의 선택 견본 그림을 **파일로만** 둔다. 서버 코드는 이 그림을 만들거나 전송하지 않는다.

## 경로와 이름 (제안, 설계 창 확정)
| 종류 | 경로 | 예 |
|---|---|---|
| 옵션 견본 | `img/opt/<키>-<값>.webp` | `img/opt/skin_tone-3.webp`, `img/opt/hair-wavy.webp` |
| 스타일 도감(기본) | `img/cat/<분류>-<id>.webp` | `img/cat/dress-a01.webp` |
| 스타일 도감(화풍별) | `img/cat/<화풍>/<분류>-<id>.webp` | `img/cat/webtoon/dress-a01.webp` (화풍: photo, webtoon, anime, render3d, illust) |

이름은 소문자·숫자·밑줄만, 키와 값 사이는 하이픈 하나. 한글 파일명 금지(주소 인코딩 문제).

## 파일 규칙 (점검 도구가 검사)
`.webp`만(내용도 WebP), 한 변 64~1536px, 파일당 200KB 이하, 애니메이션 금지, 대소문자만 다른 중복 금지, 허용 위치 밖 파일 금지.

```
python ai_creator_studio_backend_starter/scripts/check_option_images.py <그림 루트> [--expected 기대목록.json] [--strict] [--json]
```
`--expected`는 페이지가 요청하는 파일 이름 목록(JSON 배열, 예 `["opt/skin_tone-3.webp"]`)이다. 목록에는 있는데 파일이 없으면 **MISSING**(그림을 만드는 동안에는 오류가 아님 — 페이지가 폴백을 보여 줘야 함, `--strict`면 오류), 파일은 있는데 목록에 없으면 **UNEXPECTED**. 종료 코드 0 정상 / 1 규칙 위반 / 2 입력 오류. 시험: `tests/test_option_images.py`.

## 없을 때의 폴백 (페이지 쪽 계약)
- 그림이 없거나(404) 깨져도 **선택 자체는 동작**해야 한다: 이미지 `onerror` → 글자 라벨(예: 값 이름)만 보이는 칩으로 대체. 이름 없는 빈 칸을 남기지 않는다.
- 같은 이유로 **없는 그림 주소가 HTML(200)로 응답되면 안 된다.** 지금 `vercel.json`의 `/(.*)` → `/` 전체 재작성은 파일이 없으면 앱 `index.html`을 200으로 돌려준다. 그림 주소는 404가 나야 폴백(`onerror`)이 일관되게 동작한다 → 재작성 규칙에서 `/site/` 아래를 제외하는 안이 필요하다. **운영 설정 변경이라 적용하지 않았고, 미리보기 배포에서 확인한 뒤 적용(미확인).**

## 캐시 (제안, 미적용)
파일 이름에 내용 해시가 없으므로 "영구 캐시"는 위험하다(그림을 바꿔도 반영 지연). 제안: `Cache-Control: public, max-age=86400, stale-while-revalidate=604800` (하루 신선 + 일주일 재검증 허용), 그림을 교체할 때는 파일 이름에 버전 접미(`-v2`)를 붙이지 않고 하루 지연을 감수하거나 `?v=<빌드번호>`를 페이지가 붙인다. `vercel.json`의 `headers`로 `/site/img/(.*)`에 적용 — 위 재작성 변경과 함께 미리보기 배포에서 확인 후.

## 아직 없는 것
- **실제 그림**(대표님 제공 또는 생성 서비스 결과 대기, 설계 창 목록 작성 중), **기대 목록 파일**(설계 창이 페이지가 요청하는 이름 목록을 줘야 `--expected`로 점검 가능), 저작권·AI 생성 표시 기준(그림이 AI 생성이면 사람 모습 이미지의 표시 규칙과 같은 기준 적용 필요 — 법무 확인).
