# BUILD-00104 — Generated Output Review / Approval / Internal Export Manifest

## Implementation

- Added SQLite migration v9 with `generation_output_review_events` and `generation_output_export_events`.
- Review events are append-only at the database layer (UPDATE/DELETE triggers reject mutation). Every decision snapshots the linked `asset_id`, immutable `asset_version_id`, `provenance_id`, and SHA-256 checksum.
- Added workspace-scoped `GET /v1/generation-jobs/{job_id}/outputs/{output_id}/review`. It reports `asset_link_pending` / `asset_link_failed` until the Output has a verified AssetVersion; then the initial state is `pending_review`.
- Added owner/admin-only decisions: `POST .../review/approve`, `/review/request-changes`, and `/review/reject`. Change requests and rejections require a comment. A `changes_requested` output may be reviewed again; `approved` and `rejected` are terminal and require a new generated Output to replace.
- Review is allowed only for succeeded Jobs whose Output→Asset link is `linked` and whose immutable AssetVersion, provenance and checksum are present.
- Added `POST /v1/generation-jobs/{job_id}/outputs/export-manifest`. It requires every output in the succeeded Job to be linked and individually approved. The response is a canonical, SHA-256-addressed metadata manifest; an append-only export audit event is recorded.
- Export deliberately contains no binary files and explicitly sets `publication_authorized=false` and `commercial_rights_verified=false`. It is not a public URL, commercial approval, or distribution permission.
- Added `OutputReviewWorkspace` UI module and package export for output review, immutable version/provenance display, decisions, review history and gated manifest export.
